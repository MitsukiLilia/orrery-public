这个页面需要一个本地静态服务器,不能直接双击打开

Orrery 的真实代码用的是 ES module(import/export),这是酒馆加载第三方扩展的真实方式(见 docs/VERIFICATION.md §1)。浏览器规范规定:<script type="module"> 跨文件加载时走的是 CORS 校验的 fetch 流程,而 file:// 页面的 origin 是不透明的 null——不管目标文件是不是同一个文件夹, 都会被当成跨域请求直接拦掉(这不是 Orrery 的 bug,是 Chromium 对 ES module 的既定行为;经浏览器控制台实测复现过这条报错: Access to script at 'file:///.../index.js' from origin 'null' has been blocked by CORS policy)。

解法很简单,起一个本地静态服务器(任选一种,零依赖):

cd 扩展目录(orrery)&& python3 -m http.server 8420

然后访问 http://localhost:8420/test/harness.html——其余一切(mock 酒馆环境、事件按钮、IndexedDB、手机 UI)照常工作,这一步只是换个协议头。

酒馆本身永远是通过 http(s) 服务器加载扩展的,不会遇到这个限制——这纯粹是本地单文件试衣间开发时才会碰到的浏览器平台限制。
